## Glossary

### Test Generation

**Test Case Prioriization**
: APFD: area under the curver of percent tests run (x-axis) and percent of faults found
(y-axis).

**Branch Distance** `d(t)`
: How far test `t` was from flipping a branch; converts binary hit/miss
  into a smooth landscape: `fitness(t) = 1 - d(t)/(d(t)+1)`

**Mutation Testing**
: Injects small bugs (mutants) to evaluate test suite quality;
  killed = good (test caught it), survived = bad (test missed it)

**Mutant Subsumption**
: If killing mutant A always kills B, then B is redundant; drop it.
  Shrinks the search target pool substantially.

**Kill Classes**
: Group mutants that fail for same reason; search for tests that kill
  each class, not each individual mutant. Cheaper, same coverage.

**Mutation Score**
: `killed_mutants / total_mutants`; stronger proxy for test quality
  than branch coverage alone

### Fuzzing & Repair

**Grey-box Fuzzing** (AFL-style)
: Partial program analysis + random mutation; tracks edge transitions
  via a 64KB bitmap using a hashing trick on block IDs
: Fitness = new coverage found per unit time; hill-climbing on bitmap

**GenProg**
: GP-based repair; evolves AST patches (delete, replace, insert)
  against a test suite; landmark paper, later hit replication crisis

**Oracle Problem**
: "Passing tests" ≠ "correct fix"; GenProg often deleted failing paths
  rather than fixing them — fitness function diverged from true goal

**Fault Localization** (Ochiai, Tarantula)
: Rank lines by pass/fail correlation; narrows repair search space;
  SBFL is itself a rank-aggregation search problem

**Template vs. Learning-based Repair**
: Templates = human-written fix patterns; learning-based = models
  trained on GitHub fixes learn probabilistic patch shapes automatically

### Architecture & Planning

**Modular Quality (MQ)**
: Fitness for architecture recovery = intra-cluster / inter-cluster
  dependencies; maximize cohesion, minimize coupling

**Next-Release Problem**
: Constrained 0/1 knapsack: pick features to maximize value within
  budget, respecting inter-feature dependencies; GA encodes as bitstring

**Refactoring as Optimization**
: Objectives: coupling, cohesion, complexity; operators: move method,
  extract class, inline; expensive evals → good surrogate candidate

### Configuration & Test Management

**Surrogate Model**
: Cheap ML proxy (e.g., Random Forest) for expensive oracle; enables
  Bayesian Optimization to find good configs in ~100 evals vs. thousands

**SMAC / FLASH / OtterTune**
: Config-tuning tools using BO + surrogate; MySQL example: 200+ knobs,
  10x throughput variance, default config rarely optimal

**APFD** (Avg Percentage Faults Detected)
: Fitness for Test Case Prioritization; measures how early in the
  ordered suite faults appear; greedy ordering often matches GA here

**Test Suite Minimization**
: Remove redundant tests while preserving coverage; NP-hard; risk:
  rare-fault tests may look redundant but aren't

**Regression Test Selection**
: Which tests to re-run after a change; dependency analysis + search
  over subsets; CI/CD pressure → must be fast (seconds budget)

## Review Questions

**Q1** (ignore... too hard)
(a) Write the branch-distance fitness formula and state what value it
    returns when a test perfectly satisfies a branch condition.
(b) Explain why transforming binary coverage into a continuous fitness
    landscape matters for hill-climbing search. What failure mode does
    it prevent, and where does it still fall short?

**Q2**
(a) Define "killed" vs. "survived" mutant and state what each implies
    about the test suite.
(b) Mutant subsumption and kill classes both reduce search cost.
    Compare their mechanisms. When might subsumption fail to reduce
    the pool meaningfully?

**Q3**
(a) Describe the "hashing trick" AFL uses to track edge transitions
    in its branch bitmap.
(b) Grey-box fuzzing sits between black-box and white-box. Analyze
    what "fitness = new coverage per unit time" prioritizes and what
    it ignores compared to a full symbolic-execution approach.

**Q4**
(a) Name the three AST patch operators GenProg uses and the fitness
    function it optimizes.
(b) The GenProg replication crisis showed most "fixes" were test-suite
    patches. Diagnose the root cause in terms of fitness-function
    design and propose a stronger oracle.

**Q5**
(a) State the objective function and one constraint for the
    Next-Release Problem.
(b) A GA encodes feature selection as a bitstring. Explain how
    dependency constraints (feature j required if feature i selected)
    are enforced, and what happens to fitness if they are violated.

**Q6**
(a) Define Modular Quality (MQ) for architecture recovery.
(b) A search optimizer maximizes MQ on a large codebase and produces
    a partition that scores well but confuses developers. Analyze the
    tension between MQ as a proxy and true architectural quality.

**Q7**
(a) What is a surrogate model in the context of software configuration
    tuning? Give one example tool.
(b) You have a 100-eval budget and a 30-min oracle. Compare BO with
    RF surrogate vs. NSGA-II. Under what conditions would NSGA-II
    still be preferable?

**Q8**
(a) Define APFD and name the test-management task that uses it.
(b) "Greedy works surprisingly well; GA adds little" for TCP. Analyze
    why. What structural property of the TCP fitness landscape makes
    greedy competitive with evolutionary search?

**Q9**
(a) Distinguish Test Suite Minimization from Regression Test Selection.
(b) Minimization risks removing tests that catch rare faults. Design
    a fitness function or constraint that balances redundancy removal
    against rare-fault retention.
