### Question 1: Human Cognitive Bias in SE
* **Part A (2 mins):** Describe the "Complexity Bias" experiment discussed in class involving 471 adults. What was the specific numerical ratio of additive to subtractive changes observed? 
* **Part B (4 mins):** Analyze why this cognitive bias poses a specific challenge for software maintenance and refactoring. How can Search-Based Software Engineering (SBSE) tools mitigate this human limitation to ensure systems remain maintainable rather than just "growing" indefinitely? 

### Question 2: Automated Bug Repair & The Oracle Problem
* **Part A (2 mins):** In the context of GenProg and automated bug repair, define the "Fitness Function" and explain how it differs from "Correctness."
* **Part B (4 mins):** Explain the "Replication Crisis" in automated bug repair. Why might a patch that achieves 100% fitness (making all tests pass) still be considered a failure, and how does this highlight the "Oracle Problem" in search-based repair?

### Question 3: Mutation Testing and Computational Cost
* **Part A (2 mins):** Define "Mutation Testing." What is a "mutant," and what must occur for a mutant to be considered "killed"?
* **Part B (4 mins):** The cost of mutation testing ($N$ mutants $\times$ search iterations) is extremely high. Analyze how the concepts of "Subsumption" and "Kill Classes" allow researchers to reduce this search space without sacrificing the quality of the test suite evaluation.

### Question 4: Grey-Box Fuzzing Mechanics
* **Part A (2 mins):** Define "Grey-box fuzzing" and identify the primary metric used as a fitness function in tools like AFL (American Fuzzy Lop).
* **Part B (4 mins):** AFL utilizes a 64KB bitmap and a "hashing trick" to track edge transitions. Analyze how this specific implementation detail turns a binary "hit/miss" coverage metric into a smooth landscape suitable for hill-climbing or evolutionary search.

### Question 5: Feature Reduction and the "Trigram Trick"
* **Part A (2 mins):** Explain the "Trigram Trick" mentioned in the lecture for converting source code into a flat vector for analysis. 
* **Part B (4 mins):** Research discussed in class suggests that as few as 3 to 6 top words or trigrams are often sufficient for effective defect prediction. Evaluate the trade-offs of using this hyper-reduced feature set versus a full "bag-of-words" model in terms of search efficiency and model interpretability.
