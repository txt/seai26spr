# Glossary

## **Optimization Concepts**

### Core Theory
- **Pareto Frontier**: Set of non-dominated solutions where improving one objective worsens another
  - *Metaphor: Balloon Surface* - Points on frontier like skin of inflating balloon
  - *Metaphor: Frontier* - Edge/boundary of achievable solutions
- **Dominance**: Solution X dominates Y if X is better on all objectives or better on some and equal on others
- **Heaven Point**: Ideal (often unachievable) point where all objectives are perfectly satisfied
  - *Metaphor: Heaven* - Ideal point in objective space we aim toward
- **Multi-objective Optimization**: Optimizing multiple competing goals simultaneously
- **Scalarization**: Combining multiple objectives into single score (e.g., distance-to-heaven)

### Search Algorithms
- **Simulated Annealing (SA)**: Probabilistic search that accepts worse solutions early, becoming greedy over time
  - *Metaphor: Drunk Sailor* - Hot SA staggers randomly, cold SA walks straight
  - *Metaphor: Annealing* - Slowly cooling metal to reduce defects (Samurai sword)
  - *Metaphor: Hot Kitchen Plate* - Water droplet jumps when hot, settles when cool
- **Genetic Algorithm (GA)**: Population-based search using selection, crossover, and mutation
- **NSGA-II**: Non-dominated Sorting Genetic Algorithm for multi-objective optimization
- **Hill Climbing**: Greedy local search that only accepts improving moves
- **Local Optima**: Peaks that aren't the global best

### SA Components
- **Temperature**: Controls exploration vs exploitation (high = explore, low = exploit)
- **Cooling Schedule**: How temperature decreases over time (e.g., linear)
- **Metropolis-Hastings**: Acceptance criterion: accept worse solutions based on energy difference and temperature
- **Mutation**: Small random changes to create neighbor solutions
- **Energy**: Solution quality (lower is better in physics metaphor)

### GA Components
- **Population**: Set of candidate solutions (e.g., 100 random architectures)
- **Crossover**: Combining parts of two parent solutions
- **Selection**: Keeping non-dominated solutions
- **Generation**: One iteration of evaluate-select-breed cycle
- **Mutation Rate**: Percentage of features to randomly change

### Search Behavior
- **Explore vs Exploit**: Search widely vs refine best known
  - *Metaphor: Explore* - Staggering around when uncertain
  - *Metaphor: Exploit* - Walking straight line when confident
- **Greedy**: Always taking immediate best option

## **Statistics & Probability**

### Central Tendency & Spread
- **Mean (μ)**: Average value
- **Standard Deviation (σ)**: Spread around mean for numerics
  - **Welford's Algorithm**: Single-pass computation of mean and variance
  - **Running Mean**: Mean updated with each new value
  - **Second Moment (m2)**: Running sum of squared deviations
  - **Bessel's Correction**: Using n-1 for unbiased sample variance
- **Mode**: Most frequent value for symbolics
- **Entropy**: Spread/uncertainty for symbolics (in bits)
- **Variance**: Squared standard deviation

### Distributions
- **Gaussian/Normal**: Bell curve distribution
- **Uniform Distribution**: All values equally likely
- **Irwin-Hall**: Sum of uniforms approximates Gaussian
- **Central Limit Theorem (CLT)**: Sums of random variables tend toward normal
- **Z-curve**: Standard normal with μ=0, σ=1

## **Distance Metrics**

### Normalization (Required for Distances)
- **Z-score**: How many standard deviations from mean: (x - μ) / σ
- **Sigmoid/Logistic**: Maps unbounded values to (0,1) range
- **Min-Max Normalization**: Linear scaling to [0,1] using observed bounds
- **Clamping**: Restricting values to valid range (e.g., [-3, 3])

### General Distance Functions
- **Minkowski Distance**: General form: (Σ|xᵢ-yᵢ|^p)^(1/p)
- **Manhattan (L1)**: p=1, city-block distance
- **Euclidean (L2)**: p=2, straight-line distance
- **Chebyshev (L∞)**: p→∞, maximum coordinate difference

### Specialized Distances
- **Aha Distance**: Handles mixed numeric/symbolic data
- **Distance-X (distx)**: Distance in feature/input space
- **Distance-Y (disty)**: Distance in objective/output space
  - *Metaphor: Distance to Heaven* - Lower is better, measuring how far from ideal
- **Overlap Metric**: Binary 0/1 distance for symbolic attributes

### Special Cases (Data Quality)
- **Missing Values**: Unknown data marked with `?`
- **Worst-case Assumption**: Assuming maximum distance for missing values
- **Conservative Estimate**: Safe but pessimistic assumption
- **Outliers**: Extreme values beyond ±3σ

## **Machine Learning**

### Core Concepts
- **Features (X)**: Independent variables, inputs, predictors
- **Objectives (Y)**: Dependent variables, outputs, goals, targets
- **Training Data**: Known examples used to build model
- **Smoothness/Continuity**: Assumption that similar inputs give similar outputs

### Surrogate Modeling
- **Surrogate Model**: Cheap approximation of expensive evaluation
- **Nearest Neighbor**: Find most similar example, assume similar output
- **Instance-Based Learning**: Using similar past examples to predict
- **K-Nearest Neighbors (KNN)**: Average k most similar examples

### Dimensionality Reduction
- **Principal Component Analysis (PCA)**: Find directions of maximum variance
  - **Non-parametric PCA**: No assumed distribution, works on data structure directly
  - **Synthetic Dimensions**: New axes discovered from data (not raw features)
  - **Distant Points**: Extreme examples that define projection axis
  - **Projection**: Mapping data onto discovered dimension

## **Software Engineering**

### Architecture Patterns
- **Monolith**: Single large application, all code tightly integrated
- **Microservices**: Small independent services communicating over network
- **Cohesion**: How related code stays together (high is good)
- **Coupling**: How much services depend on each other (low is good)
- **God Class/Boulder**: Anti-pattern where everything is in one giant service
- **Dust**: Anti-pattern where every class is separate service

### Refactoring
- **Mono-to-Micro**: Converting monolith to microservices architecture
- **Partitioning**: Dividing classes into separate services
- **Granularity**: Size of services (fine-grained vs coarse-grained)
- **Technical Debt**: Accumulated cost of past shortcuts
- **Legacy Code**: Old, poorly documented, tangled code

### Quality Metrics
- **Business Context Sensitivity (BCS)**: Cohesion measure
- **Inter-Partition Call Percentage (ICP)**: Network overhead measure
- **Response Time**: How fast system responds
- **Modularity**: Degree of independence between components

### Infrastructure
- **Cloud Node**: Individual server in cloud
- **Network Overhead**: Cost/time of inter-service communication
- **Latency**: Network communication delay
- **Scalability**: Ability to handle increased load
- **On-Premises**: Running on local company hardware
- **Maintainability**: Ease of updating and fixing code
- **Edge Computing**: Processing on local devices, not cloud

## **Decision Making & Stakeholders**

### Stakeholder Management
- **Maintainer Profiles**: Different preferences (fine-grained vs coarse-grained)
- **Trade-offs**: Competing priorities requiring balance
- **Architectural Hypothesis**: Design strategy representing different priorities
- **Discussion Space**: Range of options to debate, not single answer
- **Fruitful Errors**: Imperfect solutions that seed productive discussion
  - *Metaphor: Fruitful vs Sterile* - Errors "full of seeds, bursting with corrections" vs sterile truth
- **Human-in-the-loop**: Keeping humans as final decision makers

### Application Domains
- **Ambulance Services**: Emergency response optimization (response time vs cost)
  - **Station Placement**: Where to position ambulances when idle
  - **Urban Focus**: Fast downtown, slower suburbs
  - **Balanced Coverage**: Medium response everywhere
  - **Budget Conscious**: Minimal stations, acceptable times

### Presentation & Explanation
- **Clustering**: Grouping similar solutions
- **Representative Solution**: Example from each cluster
- **Strategic Choice**: High-level architectural decision (5-7 clusters)
- **Analysis Paralysis**: Inability to decide due to too many options
- **Explainable AI (XAI)**: Making AI decisions understandable
- **Black Box**: System whose internals can't be inspected
- **Transparent Decision Support**: Explainable recommendations

## **Problem Complexity**

### Theoretical Limits
- **Search Space**: Set of all possible solutions
  - *Metaphor: Larger than Universe* - 2^180 > atoms in observable universe
- **Combinatorial Explosion**: Solution count grows exponentially (2^n)
- **NP-Hard**: Problems with no known efficient solution

### Key Insights
- **Backdoor Variables**: Small subset of variables that control everything (Selman 2003)
- **Unit Propagation Cascade**: Setting key variables forces all others
- **Six Interactions Rule**: Experts articulate ~6 interactions/hour

### Practical Challenges
- **Brittleness**: Sensitivity to algorithm choice and parameters
- **Hyperparameter Tuning**: Setting algorithm control parameters
- **Silver Bullet**: Myth of one universal best solution
- **Memory Constraints**: Limited RAM available
- **Lightweight Algorithms**: Low memory/CPU requirements

### Algorithm Efficiency
- **Single-pass Algorithm**: Only reads data once
- **Two-pass Algorithm**: Requires multiple data scans
- **Why Min vs Sorted**: O(n) vs O(n log n) trade-off

## **Information Theory**

### Core Concepts
- **Entropy (H)**: Average information content (bits to encode)
- **Shannon Entropy**: -Σ p log₂(p) for probability distribution
- **Information Content**: Surprise/uncertainty in message
- **Bits**: Unit of information (binary digits)
- **Log Base 2**: Logarithm for binary encoding

### Properties
- **Maximum Entropy**: When all outcomes equally likely
- **Minimum Entropy**: When one outcome certain (zero surprise)

## **Data Handling**

### Data Types
- **Numeric**: Continuous values (height, weight, temperature)
- **Symbolic/Categorical**: Discrete categories (color, type, class)

### Processing Models
- **Streaming Data**: Data arriving continuously
- **Batch Processing**: Processing all data at once

## **Implementation Details**

### Python Patterns
- **Duck Typing**: Type checking via attribute presence, not inheritance
- **Walrus Operator (`:=`)**: Assign and use value in same expression
- **Factory Function**: Function returning configured object
- **Obj Class**: Dict with attribute-style access
- **vars()**: Returns module's variable dictionary
- **Dunder Doc (`__doc__`)**: Module/function docstring

### Design Principles
- **DRY (Don't Repeat Yourself)**: Single source of truth
- **Epsilon Defense**: Adding tiny value (1/BIG) to prevent divide-by-zero
- **Defensive Programming**: Handling edge cases proactively

### Conventions
- **`i` Instance**: Variable name for "this object"
- **Goal Encoding**: Suffix `+` (maximize) or `-` (minimize)
