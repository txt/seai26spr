# Glossary & Review Questions: From Black Boxes to Small Trees

---

## Glossary

### 1. Locality & Neural Knowledge

**Distributed dogma**
  The once-dominant view that neural knowledge is smeared across
  millions of weights — no single neuron knows anything.

**Superposition**
  Networks encoding more features than neurons by overlapping
  representations. "The distributed look is an encoding trick."

**Polysemantic neuron**
  A neuron that responds to multiple unrelated concepts — a symptom
  of superposition, not true distribution (Elhage et al. 2022).

**Knowledge localization**
  Specific facts concentrate in tiny neuron subsets. Suppress them
  → recall drops ~29%. Suppress random same-count neurons → ~1.5%.

**Surgical editing**
  Zeroing localized neurons to update or erase facts/bias without
  full retraining. Works because knowledge is sparse, not diffuse.

**Superposition → sparsity principle**
  "Knowledge is sparse. Knowledge is local. Surgery works."

---

### 2. Interpretability vs. Explainability

**Explainability**
  Post-hoc approximation of a black box. Always unfaithful somewhere:
  "If an explanation were perfectly faithful to the black box,
  it *would be* the black box."

**Interpretability**
  Building the sparse structure in from the start. No black box
  to approximate. The model *is* the explanation.

**Rudin's argument**
  On structured data with meaningful features, simple models match
  complex ones. The DARPA accuracy-interpretability tradeoff curve
  was generated from no data — the axes have no units.

**COMPAS**
  130+ factor proprietary bail-risk model. Typographical errors in
  the survey can determine who goes free. Legendary black-box failure.

**CORELS**
  3-rule replacement matching COMPAS accuracy on Broward County data:
  ```
  IF age 18-20 AND male            → predict arrest
  ELSE IF age 21-23 AND 2-3 priors → predict arrest
  ELSE IF more than 3 priors       → predict arrest
  ELSE                             → predict no arrest
  ```
  Computable on a napkin. No proprietary inputs.

---

### 3. Ecological Rationality & Heuristics

**Ecological rationality** (Gigerenzer 2008)
  Simple heuristics aren't second-best — in noisy environments
  they're *more* accurate because they cannot overfit.
  "The noisier the environment, the more information you should ignore."

**Fast-and-frugal tree**
  3-question coronary care triage tree (Green & Mehr) that beat
  logistic regression *and* physicians. Still in use.

**Overfitting penalty**
  Complex models fit past noise; simple models generalize. The
  advantage of ignorance: fewer parameters = less to get wrong.

---

### 4. The Simplest Useful Model (Decision Tree)

**Header-as-schema**
  Column names encode type and role — no config files needed:
  ```python
  # [A-Z]* → Numeric      [a-z]* → Symbolic
  # *+     → Maximize     *-     → Minimize
  # *X     → Ignore       ?      → Missing value
  ```
  `EFFORT-` = numeric minimize. `origin` = symbolic independent.

**Distance to heaven (disty)**
  Single per-row score: Minkowski distance from the ideal point
  where all goals are simultaneously optimal. 0 = perfect, 1 = worst.
  ```python
  def disty(i, r):
    return minkowski(
      abs(c.norm(r[at]) - i.cols.w[at])
      for at,c in i.cols.y.items())
  ```

**Median split**
  Numerics split at the median value — one cut, not exhaustive search
  over all thresholds. Tested on 127 SE datasets: as good or better,
  far cheaper.

**Symbolic split**
  Try every unique value as a split point (equals / not-equals).

**Expected variance criterion**
  Best split minimises:
  `(n_left * var_left + n_right * var_right) / n_total`

**Leaf threshold (`the.learn.leaf`)**
  Minimum rows to justify a split. Default 3; must have 2× = 6 rows
  to recurse. Stops the tree getting absurdly deep on small data.

**treeGrow**
  Recursive binary tree builder. Returns a leaf when no valid split
  exists. "Look for the invariant: there is always a tree returned."

**Sorted-best-to-worst display**
  Leaves printed by disty score, best first. The top path is the
  actionable recommendation.

### 5. The Causal Ladder (Pearl)

**Rung 1 — See (Association)**
  "What patterns exist?" Query P(Y|X) over training data.
  In tree terms: `build + showTree`.

**Rung 2 — Act (Intervention)**
  "What does the model say about *this* row?" Route new data
  through the trained tree. Flags anomalies via leaf-vs-actual gap.
  ```python
  def treeLeaf(t, r):
    if not t.left: return t
    v = r[t.col.at]
    go = (v <= t.cut) if Num == type(t.col) else (v == t.cut)
    return treeLeaf(t.left if go else t.right, r)
  ```

**Rung 3 — Imagine (Counterfactual)**
  "What would happen if this row were different?" Clone, perturb one
  feature, re-route, observe change. Two lines:
  ```python
  def whatif(t, r, at, val):
    r2 = r[:]; r2[at] = val
    return leaf(t, r2)
  ```

**Counterfactual ≠ optimization**
  Three constraints distinguish them:
  - *Freeze the individual* (U): everything not changed stays fixed.
  - *Minimal change*: one variable at a time — actionable by a manager.
  - *Stay in observed territory*: every sibling leaf holds real rows.

**treePlan**
  Walks all other leaves, yields changes where dy > eps and at least
  one X variable differs. Output is a ranked list of single-variable
  interventions. ~6 lines of code.

### 6. Synthesis

**Simple ≠ stupid**
  "Simple models aren't just easier to understand. In noisy
  environments they're *more accurate* on future data."

**700 lines / one file**
  `ez.py` covers the full pipeline: schema, disty, tree, plan.
